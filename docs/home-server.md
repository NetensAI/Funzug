# Home-server migration status

This is a readiness-only release, not a completed home pipeline. Existing native scheduling remains active; GitHub schedule triggers and the legacy dispatcher remain unchanged. Do not run a production cutover from this release.

The restricted Phase 2 gate stages an exact public source commit. Its dry-run controller reads the existing worker's mounted configuration inside the container, retrieves BrandFlow approval metadata with GET only, compares approved slots and native handoffs with the staged queue, and reports required local credential names without values. No Meta submission, credential refresh, workflow dispatch or production-record mutation is performed. A private readiness report is saved outside the source tree.

The existing scheduler mount contains the draft integration configuration and GitHub App key. Local Instagram renewal also needs a valid FUNZUG_INSTAGRAM_LOGIN_CREDENTIAL bundle. An Actions Secret cannot be retrieved through the GitHub API. Do not paste a token into chat, place it in Git or print it in logs. A separately authorized secure provisioning/transfer path is required if no local bundle exists. Existing read-only mounts remain read-only; renewed bundles require a separately permission-restricted writable output store, not a writable source checkout or image layer.

Before activation, implement and test the complete local checkpoint/approval/reconciliation/renewal executor, a distributed owner fence honored by emergency GitHub workflows, persistent locks and audit state, pluggable failure alerts, healthchecks and rollback. An isolated dry-run must match authoritative approved IDs, slots, bindings and receipts while refusing all mutation. Quiesce and drain old executors before acquiring the home owner fence. Only then remove production schedules and draft-triggered production push execution, while retaining CI and fenced manual emergency workflows.

The eventual normal update interface is `git pull && docker compose -f home-server/compose.yml up -d --build`, but it is NOT a supported production command for this readiness-only release. Likewise, no production log/failback commands are claimed ready yet. Failback must stop home, reconcile in-flight intents and transfer the ownership fence before any manual GitHub execution. Never replay ambiguous submissions or republish already-published posts.
